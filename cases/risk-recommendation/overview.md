# 养殖风险知识库与措施推荐

## 场景

业务人员需要根据猪群当前的问题和阶段背景，从既有措施中找到可用选项，并确定展示顺序。这个项目将知识整理、推荐工程和模型选型连成一条工作链。

## 输入与输出

**输入**包括经业务审核和更新的措施库、风险问题记录、猪群阶段、季节和天气等背景，以及用于召回、过滤和排序的配置。推荐链路不只依赖知识库：问题和背景决定查询语境，措施库限定可选内容。

**输出**包括猪群推荐措施表，以及措施与触发问题的关联表。模型仅返回候选措施 ID 的顺序，程序再回查措施内容；无效或不完整结果按校验和回退规则处理。

## 本人职责

- 整理业务资料，形成千条级措施初稿；初稿经业务人员审核、修改和后续更新后，形成运行措施库。
- 负责策略推荐程序中的召回、门控、排序、缓存等模块，并处理候选融合、同一猪群多问题合并、输出校验和业务表装配。
- 固定输入及候选开展模型精排比较和补充知识实验，支持选型与交接。
- 本人确认最终选定模型已上线；线上具体版本、配置和上线日期未独立核实。

## 版本关系

较早的知识成果为 1,187 行初稿；较后的默认策略快照为 492 条。核对发现 438/492 条可按措施正文匹配，325/492 条同时匹配风险大类、风险项、子风险项及正文。这支持知识整理与运行措施库之间存在连续关系，但不表示 492 条都是从初稿原样筛选而来；完整逐行审批映射不可得。

同一项目的知识整理、推荐开发、模型评测和交接属于不同阶段，不重复包装成多个项目。K1 补充知识实验也属于后续评测阶段。
